Software Engineer Bertina Hosting · Apr 2026 – Present · Tehran, Iran

Bertina is an Iranian hosting provider: domains, shared hosting, VPS, email, SSL. I built its WHMCS Automation Engine, a FastAPI core with a PHP WHMCS addon and a Markdown knowledge vault. Support staff use it on real tickets, in Persian. It writes drafts that wait on the ticket page until a person copies, edits or approves one. It doesn't send replies itself.

  • A ticket goes through a department check, an intent classifier and a fixed set of read-only tools, then a draft built from the customer's account and the knowledge vault. A run gets at most 12 tool calls and a cost cap, per run and per day. Greeting and signature come from code, never from the model.
  • I first had a second model judge every draft. Against my own hand audit it agreed at kappa 0.07 and sent about half the drafts back, so I threw it out. Now narrow code checks do the work, each replayed on logged drafts before it was allowed to act, plus a few yes/no questions to an outside probability model with personal data masked first. A failed check gets one targeted redraft. Every path ends with a person.
  • Access is a default-deny policy file, and a tool it doesn't list is refused. Four tiers: reads, low-risk writes like notes and status, changes that wait for approval, and suspend, terminate, cancel and refund only in person. An approval stores a hash of the exact arguments, so if one changes the action needs approval again.
  • Reads go through one parameterized query function into the 40 GB production MySQL, with a LIMIT, a 10 second timeout and per-table read-only grants. Account changes go through the WHMCS API. One unindexed scan took 43.8 seconds; an index on the last-reply column made it 0.58, and a query-plan test in CI now fails any tool query that can't use an index unless the scan is listed as accepted.
  • Ticket text and tool results are untrusted and quarantined; knowledge vault pages are the one trusted channel, so a customer's message can't become an instruction. The submitter's IP is stripped before any model sees it. The same core runs Ask Agent, which answers staff from live data under department-level access rules, and Rewrite, which restyles a reply into house style. Each ticket also updates a per-customer profile that the next draft reads.
