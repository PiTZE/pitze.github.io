Software Engineer Bertina Hosting · Apr 2026 – Present · Tehran, Iran

Bertina is an Iranian hosting provider (domains, shared hosting, VPS, email, SSL). I designed and built WHMCS Automation Engine: FastAPI core, PHP WHMCS addon, Markdown knowledge vault. Customer replies are in Persian. The ticket pipeline runs in production; draft-assist surfaces suggest replies to staff and do not send on their own.

  • Classify the request, gather the account, draft a Persian reply, then a second model verifies every factual claim against that account. Fail twice, or hit a destructive action, and a person takes it.
  • Tool access is policy-as-code, default-deny. Four tiers: read, reply, async approval, in-person for suspend / terminate / refund. Approvals bind to a hash of the exact action shown.
  • One parameterized SQL path into ~40 GB WHMCS: statement timeouts, least-privilege grants, customer-account writes only through the WHMCS API. Unindexed lastreply scan: 43.8s; with an online index: 0.58s. CI fails any new query that filters a growing table off-index.
  • Prompt-injection handling is structural, not filter-based: vault pages are trusted, ticket text is quarantined. A prompt inside a customer message cannot become an instruction.
  • Same core runs Ask Agent (department allowlist redacts fields before the prompt), Agent Rewrite for house style, and an approvals queue. Agent Rewrite never sends the greeting or signature to the model. It returns line numbers; the code slices.
  • Routing, tone, escalation, and field ACL live in the Markdown vault. Support edits and commits; the core reindexes without a release. On 1,000 real production tickets, about 80% were answered or resolved through follow-ups and clarifying questions without a human; about 20% were escalated with full context (account state, draft reply, verification notes) so support could act in one step.
